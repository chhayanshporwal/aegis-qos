## 0. STRICT ANTI-HALLUCINATION RULES FOR THE AI CODING AGENT
1. **NO FAKE BENCHMARKS OR MOCK NUMBERS:** Every latency, jitter, packet loss, throughput, queue depth, Jain's fairness index, and CPU metric MUST come from real packets traversing Linux network namespaces (`ip netns`) shaped by Linux Traffic Control (`tc`) and generated by `iperf3` / `ping` / Python UDP sockets.
2. **NO PAYLOAD DECRYPTION (ZERO-DPI):** Never inspect L7 packet payloads. Extract only L3/L4 statistical metadata (packet byte lengths, inter-arrival times, packet counts, protocol, and 5-tuple).
3. **BIDIRECTIONAL SHAPING REALITY (CRITICAL LINUX NETWORKING RULE):**
   - In our 4-namespace topology, **Download traffic** flows from `ns_server` -> `ns_wan_netem` -> `ns_router` -> `ns_clients`.
   - Therefore, inside `ns_router`, download traffic exits **`veth_rtr_lan`** (towards `ns_clients`) and upload traffic exits **`veth_rtr_wan`** (towards `ns_wan_netem`).
   - Likewise, inside `ns_wan_netem`, the simulated ISP WAN bottleneck (`tc netem`) MUST be applied to **`veth_netem_in`** (egress towards `ns_router` for downloads) AND **`veth_netem_out`** (egress towards `ns_server` for uploads).
   - Inside `ns_router`, apply the 4-class `HTB` + `fq_codel` hierarchy on **`veth_rtr_lan`** (Downstream shaping) AND **`veth_rtr_wan`** (Upstream shaping), plus attach an `ifb0` ingress redirect on `veth_rtr_wan` so evaluators can inspect both egress and ingress `tc` hooks.
4. **DISABLE VETH CHECKSUM OFFLOADING:** Virtual ethernet (`veth`) interfaces in Linux namespaces corrupt TCP performance under `tc netem` unless `ethtool -K <iface> tx off rx off tso off gso off gro off` is executed on all veth endpoints during setup.
5. **DUAL-STACK IPv4 & IPv6 PARITY:** Every namespace link, route, `iptables`/`ip6tables` packet mark (`fwmark`), and `tc filter` rule MUST be configured for both IPv4 and IPv6.
6. **ATOMIC EXECUTION & SAFE-STATE ROLLBACK:** All `tc` updates must be applied via `tc -b <batchfile>`. If `tc` returns a non-zero exit code, or if the Watchdog detects CPU > 10% or anomalous loss, the system must immediately roll back to a known safe state (`tc qdisc replace dev <iface> root fq_codel`).
